# 版本说明 · v0.2.0（第一版可交付）

> 发布日期：2026-06-08 · 状态：**可交付使用（信号检测 + 模拟盘执行）**

## 这是什么版本

预测市场套利扫描器的**第一个可交付版本**。它实时从 **Polymarket** 和 **predict.fun** 两个平台摄取行情，跨平台匹配等价市场，检测计入费用与价差的套利机会，把机会跟踪为有状态的「信号」，并通过只读 HTTP API 与告警呈现。还内置了**模拟盘（paper trading）双腿执行**，可在不动真钱的情况下演练完整交易链路。

一句话：**除了真实资金下单，整条流程已经能跑、能用、能演示。**

## ✅ 本版本能做什么

| 能力 | 说明 |
|---|---|
| 双平台行情摄取 | Polymarket（Gamma + CLOB）、predict.fun（BNB Chain 链上市场，只读 API），各自独立刷新循环、故障隔离 |
| 跨平台匹配 | 词法/归一相似度 + **金标准 cross_ref 关联**（predict.fun 自报对应的 Polymarket 市场，匹配置信度 1.0） |
| 套利检测 | 基于 ask 价、计入费用与价差的净利润率，按最薄一腿流动性限制规模 |
| 信号生命周期 | 机会被跟踪为信号：`OPEN → SUSTAINED → CLOSED`，记录峰值利润率与持续时长，产出可审计事件流 |
| 信号持久化 | SQLite 落盘，跨重启不丢、可对账（默认 `signals.db`） |
| 数据接入韧性 | 每个平台适配器带限流 + 指数退避重试 + 熔断器，遵守平台速率限制 |
| 只读 API | `/markets` `/groups` `/opportunities` `/signals` `/signals/events` `/health` `/metrics` `/config/alerts` |
| 告警 | 满足条件的新信号经日志 / Webhook 通道发出，带重试与去重 |
| 可观测性 | JSON 结构化日志 + `/metrics` 运行指标 |
| 模拟盘执行 | `PaperExecutionAdapter` + `ExecutionEngine`：双腿下单、**双腿原子性**（一腿失败自动平掉另一腿、残余敞口检测），订单/计划可持久化 |

测试：**477 个自动化测试全部通过**，离线确定性运行。

## ❌ 本版本还不能做什么（明确边界）

- **真实资金下单**：两个平台的真实链上下单（Polymarket 在 Polygon、predict.fun 在 BNB Chain）需要**钱包私钥 + EIP-712 链上签名 + 真实资金**，属于后续单独的一步，需你提供测试钱包与资金后联调。当前的执行只在**模拟盘**进行。
- **Kalshi 交易**：按项目决定，暂缓（等风控与限制就绪），默认配置中已禁用。Kalshi 行情适配器代码仍在，可手动启用做只读。
- **API 鉴权**：只读 API 当前**无鉴权**。不要直接暴露到公网，请置于带认证的反向代理 / 网关之后。
- **风控闸门、半自动确认流**：尚未实现（计划中的切片 G/H），因此当前**不建议**接真实下单。

## 快速开始

### 1. 安装

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"
```

### 2. 跑一遍完整演示（推荐先做这步，无需联网、无需密钥）

```bash
.venv/bin/python demo.py
```

会用伪行情驱动 Polymarket + predict.fun，打印从行情 → 匹配 → 套利 → 信号 → API → 模拟盘双腿执行的全过程。

### 3. 启动真实服务

默认配置（`config.yaml`）已**开箱即用**：启用 Polymarket + predict.fun，两者均无需密钥即可读公开行情；Kalshi 默认禁用。

```bash
# 启动只读 API（后台自动摄取 + 周期检测）
.venv/bin/python -m uvicorn scanner.app:app --host 127.0.0.1 --port 8000
```

启动后服务会持续摄取行情并检测信号。查询：

```bash
curl -s http://127.0.0.1:8000/health          # 各平台健康 + 计数
curl -s http://127.0.0.1:8000/markets         # 已排名市场（含数据新鲜度）
curl -s http://127.0.0.1:8000/opportunities   # 当前套利机会（按净利润率降序）
curl -s http://127.0.0.1:8000/signals         # 当前活跃信号（状态/峰值/时长）
curl -s http://127.0.0.1:8000/signals/events  # 信号事件流（可审计）
curl -s http://127.0.0.1:8000/metrics         # 运行指标
```

也可访问 `http://127.0.0.1:8000/docs` 查看自动生成的 OpenAPI 文档。

### 4. 跑测试套件

```bash
.venv/bin/python -m pytest      # 477 个测试，离线确定性
```

## 切换到真实实时数据

本版本已做过**真实 API 连通验证**（非 mock）：

| 平台 | 真实数据现状 | 需要准备 |
|---|---|---|
| **Polymarket** | ✅ 生产 API 直接可用，**无需密钥**。实测可拉到真实市场（价格/bid/ask/成交量/流动性齐全） | 无 |
| **predict.fun** | ⚠️ 生产 API（`api.predict.fun`）**必须有 API key**（无 key 返回 401）；测试网（`api-testnet.predict.fun`）无 key 可读但数据稀疏 | predict.fun 生产 API key |

**默认配置开箱即用**：Polymarket 走生产真实数据 + predict.fun 走测试网（无需任何密钥即可启动）。

### 如何申请 predict.fun 生产 API key

predict.fun 的 API key 通过其 **Discord 支持工单**申请（官方 FAQ 明确说明）：

1. 加入 predict.fun Discord：<https://discord.gg/predictdotfun>
2. 开一个 support ticket（支持工单），说明要申请 REST API key
3. 拿到 key 后：
   - 设环境变量：`export PREDICTFUN_API_KEY=你的key`
   - 编辑 `config.yaml` 的 `predictfun` 段：把 `options.base_url` 改为 `https://api.predict.fun`，并加一行 `api_key_env: PREDICTFUN_API_KEY`

> 说明：predict.fun key 仅用于**读取生产行情**（提高速率、解锁生产数据）。真实**下单**另需钱包私钥 + 链上资金，是后续单独的一步。Mainnet 默认速率 240 请求/分钟。

切换后两个平台都是真实生产实时数据，即可跑出真实的跨平台套利信号。

## 配置速览（`config.yaml`）

| 配置 | 默认 | 说明 |
|---|---|---|
| `refresh_interval_seconds` | 30 | 每平台刷新间隔（≤60s） |
| `staleness_threshold_seconds` | 60 | 超时标记过期、排除出套利 |
| `match_confidence_min` | 0.6 | 进入套利的最低匹配置信度 |
| `signal_store_path` | `signals.db` | 信号持久化路径；留空则用内存 |
| `similarity_backend` | `lexical` | 匹配相似度后端；`normalizing` 启用同义词归一增强召回 |
| `json_logging` | `false` | 结构化 JSON 日志开关 |
| `alerts.criteria.min_net_profit_margin` | 0.02 | 告警触发的最低净利润率 |

平台默认：**polymarket（启用）+ predictfun（启用）+ kalshi（禁用）**。
- predict.fun 行情默认无需密钥；如有 API key，设环境变量 `PREDICTFUN_API_KEY` 并在该平台配置加 `api_key_env: PREDICTFUN_API_KEY` 获取更高速率。

完整配置与运维见 [07-部署与运维.md](./07-部署与运维.md)，API 细节见 [05-API文档.md](./05-API文档.md)。
