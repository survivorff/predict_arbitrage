# 13 · 匹配算法重设计 与 正确性红线

本文回答两个核心问题：
1. 匹配（判定两个市场是不是「同一事件」）为什么必须重新设计，方案是什么，需要你提供什么。
2. 这个项目要帮用户**真实获利**，核心是什么、什么绝不能出错、必须严格控制——逐条列出、标注已解决/缺口。

> 触发本文的真实事件：仪表盘上「Will Mexico win the 2026 FIFA World Cup?」显示 122% 套利。排查发现它把 Polymarket 的「夺冠」(墨西哥 1.4%) 和 predict.fun 的「赢得 A 组」(墨西哥 56%) 当成了同一事件——**这不是套利，是匹配错误，实盘会直接亏钱**。

---

## 第一部分：匹配算法为什么要重设计

### 根本问题
旧匹配用「标题词法/复合相似度加权求和」判断是否同一事件。缺陷是**致命的**：
- 词法相似度measure 的是「词重叠」，不是「事件身份」。
- 两个市场可以 90% 的词相同却是不同事件（夺冠 vs 赢小组、$100k vs $110k、2025 vs 2026）。
- 一个**语义决定性的差异**（4 次 vs 7 次）在加权求和里只占一个 token 的权重，被淹没。
- 软加权意味着「足够高的词重叠可以盖过关键差异」——这正是 Mexico bug 的成因（相似度 0.864 > 0.85 阈值）。

### 设计原则（已确立）
**匹配必须保守。判定「同一事件」要求在所有身份决定性维度上都有正证据；任一决定性维度不一致 = 硬否决（veto）。**

依据**不对称代价**：
- 漏配（false negative）= 错过一个套利机会 = **不亏钱**。
- 错配（false positive）= 把两个不同事件当套利 = **真亏钱**。

所以宁可漏，不可错。决定性维度用硬 veto，不用软加权。

### 身份决定性维度（一个二元预测市场「问的是什么」）
| 维度 | 例子 | 现状 |
|---|---|---|
| 主体/实体 | Mexico / Bitcoin / Trump | 软评分（entity_overlap） |
| 谓词/动作 | win / close above / be elected | 软评分（title） |
| **赛段/范围** | 夺冠 vs 赢 A 组 vs 进半决赛 | ✅ **已加硬 veto**（`_scope_mismatch`） |
| **数字阈值** | 4 次 vs 7 次；$100k vs $110k | ✅ **已加硬 veto**（`_number_mismatch`） |
| **结算日期/年份** | by 2025 vs by 2026；同事件下按月份分档子市场 | ✅ 数字 veto(年份) + **结算日期硬 veto**（`_date_mismatch`，相差 >7 天即判不同事件） |
| 结算来源/判定标准 | 谁、按什么规则、何时判定 | ❌ 缺口（见下） |

### 已落地的修复（本轮）
1. **赛段 veto** `_scope_signature`/`_scope_mismatch`：小组赛及组别、淘汰赛轮次（ro16/ro32/quarterfinal/semifinal）、advance/qualify。不一致 → `composite_score` 返回 0。
2. **数字 veto** `_number_mismatch`：归一标题中的显著数字（行权价/次数/年份，处理 $、逗号、k/m/b 后缀），集合不一致 → 返回 0。
3. 两个 veto 都同时保护 **cross_ref 金标准路径**和**普通评分路径**。
4. 真实验证：Mexico 虚假套利消失，套利机会 3→0；新增 11 个回归测试。

### 仍存在的局限（诚实说明）
- veto 是**启发式**，针对已观察到的错配模式（体育分层、数字阈值）。新题材可能有新错配模式（如「当选 vs 提名」、「连任 vs 首次当选」、不同结算时区/来源）。
- 词法相似度对**同义改写**召回有限（已有 `NormalizingLexicalSimilarity` 同义词增强兜底，但非真正语义理解）。
- cross_ref（平台自报关联）可能本身就错，veto 能挡掉标题明显不符的，但挡不住「标题相似但结算标准不同」的。

### 重设计方案（分阶段，需你决策）

**阶段 A（已完成）：决定性维度硬 veto。** 赛段、数字阈值、年份。低成本、立竿见影。

**阶段 B（建议下一步，需你拍板）：结构化「市场指纹」匹配。**
不再直接比标题，而是把每个市场解析成结构化指纹：
```
{subject, predicate, scope, threshold, resolution_date, resolution_source}
```
匹配 = 指纹逐字段比对（决定性字段必须等，描述字段可软比）。解析方式两选一：
- **B1 规则解析**（零成本、可控、确定）：扩展现有正则/词典，覆盖更多题材。优点：无外部依赖、可测、免费。缺点：要持续维护规则，覆盖面有限。
- **B2 LLM/嵌入语义解析**（强，但需外部服务）：用 LLM 把标题解析成结构化指纹，或用 embedding 判断语义等价。优点：覆盖面广、抗改写。缺点：**需要 API key（OpenAI 等）、有成本、有延迟、结果需缓存、且 LLM 本身可能出错需校验**。

**阶段 C：结算等价性校验（见红线 C）。** 需要平台提供结算规则元数据，或人工标注。

### 我需要你提供/决策的
1. **阶段 B 走哪条路？**
   - B1（纯规则，免费，我自己做，覆盖面渐进扩大）——**推荐先做这个**；
   - B2（接 LLM/embedding，覆盖面大但要 key + 成本）——若要，请提供 OpenAI（或其他）API key（环境变量注入）+ 可接受的每日调用成本上限。
2. **匹配置信度阈值**：当前 `match_confidence_min=0.85`。要不要更保守（如 0.9）？保守 = 更少机会但更少错配。
3. **是否要求「人工确认匹配」**：高价值机会下单前，是否要你人工确认「这俩确实是同一事件」？（最强的防错配闸门，零算法风险。）
4. **题材优先级**：你最关心哪些题材（体育/政治/加密/经济）？我按优先级补 veto 规则。

## 第二部分：帮用户获利的核心 与 不能出错的红线

### 价值链（用户真正赚到钱，当且仅当全链路都对）
```
真实行情 → 同一事件匹配 → 结果对齐 → 套利数学 → 可成交性 → 双腿原子性 → 结算等价
```
任一环错 → 要么算出假机会（亏钱），要么真机会执行失败（亏钱/裸敞口）。

### 红线清单（按「出错=多大灾难」排序）

#### Tier 0 — 灾难级：false positive = 几乎必然真亏钱
| # | 红线 | 错了会怎样 | 状态 |
|---|---|---|---|
| A | **事件身份匹配**：两市场必须是同一真实事件 | 拿不相关的两个赌注当对冲，122% 假套利 | ✅ 赛段+数字 veto 已堵；结构化指纹待做（阶段 B） |
| B | **结果对齐/极性**：YES@A 必须真正等于 YES@B（或正确反转的 NO） | 极性反了 → 「买 YES+买 NO」变「买 YES+买 YES」= 双倍单边裸赌，不是套利 | ⚠️ 有 `map_outcomes`+`inverted`，但极性靠标题词判断（not/won't），**需加强校验**（缺口 B-1） |
| C | **结算等价**：同一判定来源、同一结算时间、同一精确口径 | 口径/时间/来源不同 → 不是真互补，可能两边都输 | ⚠️ **结算日期硬 veto 已加**（`_date_mismatch`，区分同标题不同结算窗口的子市场）；结算来源/口径(谁按什么规则判定)校验仍缺口 |

#### Tier 1 — 严重：侵蚀或抹掉真实利润
| # | 红线 | 状态 |
|---|---|---|
| D | **可成交价与流动性**：用真实 ask（穿价成本）、按实际深度限规模、计滑点 | ✅ 基于 ask + 流动性限规模 + **已实现收益按真实成交价核算**（能识破滑点致亏） |
| D-2 | **隐含概率背离 = 不可靠信号**：同一事件两平台隐含概率本应接近；背离大（如「7 次降息」Polymarket 0.4% vs predictfun 17.6%、「5 次降息」0.4% vs 49%）说明一侧定价脏/薄/结算口径不同——**大价差是危险信号不是中奖**。真正的跨平台套利价差很小（1-5%）；20%+ 几乎一定是数据/匹配问题 | ✅ **仪表盘警告 + 后端闸门**（`max_implied_prob_divergence` 默认 0.10，背离超阈值直接跳过） |
| D-3 | **可成交规模/净 gas 利润**：薄盘（如 $65 深度）的机会，链上 gas 可能吃掉全部利润 | ✅ **后端闸门**（`min_recommended_size_usd` 默认 20）+ 仪表盘 gas 提示 |
| E | **费用**：计入各平台真实手续费 + 链上 gas | ⚠️ 有费用模型，但 Polymarket 费率固定 0、gas 未计（缺口 E-1） |
| F | **新鲜度**：绝不用过期报价交易 | ✅ staleness 阈值 + 过期组不评估 |
| F-2 | **覆盖一致性/实时性**：predictfun 按成交量取前 N 个市场，低成交量的已匹配市场会在周期间轮换出抓取范围，导致机会忽有忽无 | ✅ **已修**：`PredictFunAdapter.pinned_ids` 固定抓取已匹配市场（`/v1/markets/{id}`），不受 top-N 轮换影响 |
| G | **双腿原子性**：绝不留单边裸敞口 | ✅ 执行引擎补救 + 残余敞口告警 |

#### Tier 2 — 资金安全控制
| # | 红线 | 状态 |
|---|---|---|
| H | **风控闸门**：敞口上限、滑点、最小利润率、dry-run、人工确认 | ✅ 已实现且敞口上限已真正生效 |
| I | **密钥/资金安全**：私钥绝不上服务器 | ✅ 设计为浏览器钱包签名 |
| J | **稳定性**：摄取不假死、数据不陈旧累积 | ✅ 已修（httpx 自愈 + 市场清理） |

### 待解决缺口（按优先级，建议逐个清掉）
1. **B-1 结果对齐极性强校验**（Tier 0）：当前靠标题 not/won't 判极性，脆弱。应在下单前对每条腿做「我买的这个结果，赢钱条件是否真与对腿互补」的显式校验，疑似反转直接拒绝。
2. **C 结算等价校验**（Tier 0）：✅ **结算日期 veto 已落地**（`_date_mismatch`：Polymarket 取 endDate、predict.fun 从描述文本解析，相差 >7 天判不同事件，修复同事件下按月份分档子市场的错配风险）。**剩余缺口**：结算来源/口径（谁、按什么规则判定）元数据校验；长期需平台元数据或人工标注。
3. **D-2 隐含概率背离后端过滤/降权**（Tier 1，已在仪表盘警告）：背离 > 阈值（建议 10-15 个百分点）的机会，后端应标记低可靠或排除。**需你定阈值**。
4. **D-3 最小可成交规模/净 gas 利润下限**（Tier 1）：过滤「$65 深度、gas 吃掉利润」的尘埃机会。**需你定下限**（建议按链上 gas 成本，如净利润 > $X 才上榜）。
5. **F-2 已匹配市场固定抓取**（实时性）：cross_ref 已确认的市场对，应固定纳入抓取，不随成交量 top-N 轮换而忽有忽无。
6. **E-1 费用/gas 完整计入**（Tier 1）：动态读取各平台真实费率 + 估算链上 gas，纳入净利润率。
7. **阶段 B 结构化指纹匹配**（Tier 0 加固）：把匹配从「比标题」升级为「比结构化字段」。

### 真实案例复盘：「Will 7 Fed rate cuts happen in 2026?」20.8% 假套利
- 算术：Polymarket 买 YES@0.4¢ + predictfun 买 NO@82.4¢ = 82.8¢ < $1 → 20.8%。
- 真相：Polymarket（$2.3M 深度市场）定 P(7次)=0.35%，predictfun（成交量不可得、薄盘）定 17.6%——50 倍背离，"套利空间"全靠 predictfun 离谱定价。
- 流动性仅 $65（Polymarket YES ask 深度），毛利约 $13.5，链上 gas 易吃掉。
- 实时性：再查时机会已消失（predictfun 该市场轮换出 top-200）。
- 同类：「5 次降息」Polymarket 0.4% vs predictfun 49%。
- 教训：**大价差（20%+）几乎一定是数据/匹配/口径问题，不是免费的钱**；真套利价差很小。已在机会卡显式警告。

### 一句话总结
**帮用户赚钱的头号前提，是「绝不把两个不同事件当成套利」**——这是唯一一类「看着稳赚、实则必亏」的错误。其余红线（可成交性、费用、双腿原子性、风控）侵蚀利润或带来执行风险，但不会凭空造出假机会。所以**匹配正确性（Tier 0）是重中之重，必须用硬 veto + 结构化指纹 +（高价值时）人工确认三重保险**，而不是靠一个相似度阈值。
