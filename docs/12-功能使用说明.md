# 12 · 功能使用说明

本文是面向使用者的操作手册：如何启动、如何看懂仪表盘、各 API 怎么用、如何配置、以及交易功能的安全边界。技术设计见 [02-架构设计](./02-架构设计.md)、[04-模块详解](./04-模块详解.md)。

## 1. 这是什么

一个**预测市场跨平台套利信号工具**：实时抓取 Polymarket 与 predict.fun 两个平台的行情，自动识别「同一事件」的等价市场，计算跨平台套利机会（在不同平台分别买入互补结果，若总成本 < $1 即有无风险价差），并提供半自动下单能力（默认 dry-run 演练，不动真钱）。

核心数据流：

```
行情摄取 → 跨平台匹配 → 套利检测 → 信号生命周期 → 风控 → 半自动确认 → (dry-run) 执行
```

## 2. 快速启动

### 2.1 环境准备
```bash
# 进入项目目录，使用项目自带虚拟环境
cd /Users/saber/predict_arbitrage
# 安装依赖（首次）
.venv/bin/pip install -e .
```

### 2.2 启动服务
```bash
# predict.fun 生产 API 需要 key（通过环境变量传入，绝不写进文件）
PREDICTFUN_API_KEY='你的key' .venv/bin/python -m uvicorn scanner.app:app --host 127.0.0.1 --port 8000
```

启动后：
- **仪表盘**：http://127.0.0.1:8000/
- **交互式 API 文档**：http://127.0.0.1:8000/docs

> 不带 `PREDICTFUN_API_KEY` 也能启动：Polymarket 公开行情无需密钥；predict.fun 生产 API 无 key 会优雅降级（读不到 predict.fun 行情，但服务不崩）。

### 2.3 运行测试
```bash
.venv/bin/python -m pytest -q
```

## 3. 仪表盘各卡片怎么看

| 卡片 | 内容 | 交互 |
|---|---|---|
| 顶部横幅 | 工具说明与数据流 | — |
| 运行概览 | 在监控市场数、等价组、套利机会、信号、周期耗时等 | — |
| 钱包 | 连接浏览器插件钱包（MetaMask），看地址/余额/网络 | 连接、切换 BNB Chain/Polygon（只读） |
| 账户与持仓 | 各平台**模拟盘**余额、当前持仓、已占用敞口 | — |
| 平台健康 | 各平台抓取状态、熔断、成功/失败计数、最近成功时间 | — |
| 交易计划 | 通过风控的待确认计划 | 确认 / 拒绝 / 预览订单 |
| 套利机会 | 净利润率为正的跨平台套利 | 搜索/排序，点行看净利润率走势 |
| 市场行情 | 在监控的所有市场 | 搜索/平台筛选/**类目筛选**/排序，点行看盘口+价格走势 |
| 活跃信号 | 信号生命周期（OPEN→SUSTAINED→CLOSED） | — |
| 跨平台等价组 | 同一事件的等价市场组合 | 搜索/置信度筛选，点行看双平台价差 |

数据新鲜度：套利/市场卡顶部有「● 数据实时（X秒前）」指示，绿=实时、黄=稍旧、红=过期。

## 4. 常用 API

只读端点（无需鉴权）：
- `GET /markets`、`GET /markets/{platform}/{market_id}`（盘口明细）
- `GET /groups`、`GET /groups/{group_id}`
- `GET /opportunities`、`GET /opportunities/{group_id}/history`
- `GET /markets/{platform}/{market_id}/history`
- `GET /signals`、`GET /signals/{group_id}`、`GET /signals/events`
- `GET /health`、`GET /metrics`

交易端点（可选鉴权，见 §6）：
- `GET /trade/plans`、`GET /trade/plans/{id}`
- `POST /trade/plans/{id}/confirm`、`POST /trade/plans/{id}/reject`
- `GET /trade/balance`、`GET /trade/positions`、`GET /trade/exposure`

完整字段见 [05-API文档](./05-API文档.md) 或 `/docs`。

## 5. 配置（config.yaml）

关键项（完整见文件内注释）：

```yaml
scanner:
  refresh_interval_seconds: 30      # 行情刷新间隔
  staleness_threshold_seconds: 60   # 超过此年龄的数据标记过期、不参与套利
  match_confidence_min: 0.85        # 匹配置信度阈值（也是匹配引擎阈值）
  signal_store_path: signals.db     # 信号持久化（留空=内存）
  history_store_path: history.db    # 行情/机会历史时间序列
  trade_store_path: trades.db       # 交易计划/订单持久化
  # trade_api_key_env: SCANNER_TRADE_API_KEY  # 交易 API 鉴权（见 §6）

platforms:
  - name: polymarket
    options:
      page_size: 100
      max_markets: 200
      categories: [politics, elections, sports, geopolitics, economy, crypto]  # 按火热类目优先抓取
  - name: predictfun
    api_key_env: PREDICTFUN_API_KEY
    options:
      base_url: https://api.predict.fun
      max_markets: 200

risk:                               # 风控（下单前最后闸门）
  max_trade_size_usd: 100.0         # 单笔上限
  max_market_exposure_usd: 200.0    # 单市场敞口上限
  max_total_exposure_usd: 1000.0    # 总敞口上限
  max_slippage: 0.02                # 滑点上限
  min_net_profit_margin: 0.02       # 最小净利润率
  dry_run: true                     # 安全：true=只演练不下真单
  require_confirmation: true        # 需人工确认
```

## 6. 交易功能与安全边界

### 当前能做什么
- **检测**：实时发现跨平台套利机会（已计入费用与价差）。
- **风控**：每个机会过 7 条风控（净利润率/新鲜度/滑点/单笔/单市场/总敞口/余额），给出核准规模。
- **半自动确认**：通过风控的机会生成待确认计划，由你在仪表盘或 API 确认/拒绝。
- **模拟盘成交**：确认后由模拟盘（paper）真实模拟成交——**更新持仓、扣减模拟余额、按实际成交价核算每笔已实现收益**（默认配置即生效，不动真钱）。`dry_run` 只抑制真实适配器；模拟盘始终模拟成交。
- **真实收益审计**：每笔完成的交易计算「赔付 − 实际成交成本」，标记是否真盈利（滑点/费用可能使检测为正的套利实际亏损）。见 `GET /trade/pnl` 与仪表盘交易计划卡「真实收益」列。
- **模拟盘账户**：余额/持仓/敞口/盈亏可视化（当前是 paper 模拟盘，非真实资金）。
- **钱包只读 + 真实链上余额**：浏览器钱包连接看地址/余额；配 `polygon_rpc_url` + `wallet_address` 后可只读显示真实 USDC 余额（无需私钥）。

### 当前不能做什么（需进一步开发 + 你的授权）
- **真实下单**：尚未接入真实执行适配器，无法向平台提交真实订单。
- 真实下单的硬前置：真实执行适配器（切片 I）+ 前端 EIP-712 签名（切片 N）+ 你的真实账户/资金/明确授权。详见 [11-真实下单测试准备清单](./11-真实下单测试准备清单.md)。

### 交易 API 鉴权（建议真实交易前开启）
```bash
# 1. config.yaml 取消注释： trade_api_key_env: SCANNER_TRADE_API_KEY
# 2. 启动时设环境变量：
SCANNER_TRADE_API_KEY='强随机串' PREDICTFUN_API_KEY='...' .venv/bin/python -m uvicorn scanner.app:app
# 3. 调交易端点时带头：  -H "X-API-Key: 强随机串"
```
开启后所有 `/trade/*` 端点要求正确 `X-API-Key`（否则 401）；只读端点不受影响。

### 安全红线
- 默认 dry-run；真实下单必须显式 `dry_run: false` + 人工确认。
- 私钥/助记词只你掌握，绝不入代码、日志、API 响应、git。
- 任何时候不放任单边裸敞口；双腿失败有补救与告警。
- 真实下单前必须先通过真实 API 只读连通验证。

## 7. 数据存哪、重启是否保留

见 [10-数据持久化策略](./10-数据持久化策略.md)。简述：行情/机会=内存瞬时；信号/事件、历史时间序列、交易计划/订单=SQLite 持久。

## 8. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 仪表盘「服务降级」、平台熔断 open | 网络中断/平台 API 故障 | 网络恢复后会自愈（连接自动重建）；持续异常看服务日志 |
| predict.fun 无行情 | 缺 `PREDICTFUN_API_KEY` 或 key 失效 | 检查环境变量；生产 API 需有效 key |
| 套利机会长期为 0 | 正常——真实跨平台套利罕见，且风控阈值严格 | 无需处理；可适当下调 `match_confidence_min` 观察更多匹配 |
| 交易端点返回 401 | 配了 `trade_api_key_env` 但请求没带正确 `X-API-Key` | 带正确头，或取消鉴权配置 |
| 数据年龄持续 >60s | 摄取卡住 | 看日志；重启服务 |
