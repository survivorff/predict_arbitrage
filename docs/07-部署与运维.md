# 07 · 部署与运维

## 1. 环境要求

- Python（目标 3.11+；当前开发环境 3.9.6 也可运行，代码向前兼容）。
- 依赖见 `pyproject.toml`：运行时 `httpx`、`websockets`、`fastapi`、`uvicorn`、`pydantic>=2`、`pyyaml`；开发 `pytest`、`pytest-asyncio`、`respx`。

## 2. 安装

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -e ".[dev]"
```

## 3. 配置

扫描器通过 YAML 文件配置，默认读取仓库根目录的 `config.yaml`（可用 `SCANNER_CONFIG` 环境变量覆盖路径）。

```yaml
scanner:
  refresh_interval_seconds: 30      # 每个适配器的刷新间隔（≤60s）
  fetch_timeout_seconds: 30         # 单次抓取超时，超时则隔离该平台
  staleness_threshold_seconds: 60   # 超过此年龄标记过期，排除出套利（默认 60s）
  match_confidence_min: 0.6         # 进入套利评估的最低匹配置信度
  signal_store_path: signals.db     # 信号持久化路径；省略或留空则用内存（重启丢失）
platforms:
  - name: polymarket
    enabled: true
    fee_model: { type: flat, rate: 0.0 }
  - name: kalshi
    enabled: true
    api_key_env: KALSHI_API_KEY     # 该环境变量缺失时，仅禁用此适配器
    fee_model: { type: kalshi }
  - name: predictfun
    enabled: true
    api_key_env: PREDICTFUN_API_KEY # 可选：填了则缺失该变量时只禁用此适配器；
                                    # 想在无密钥下公开读取行情可省略此行（适配器会优雅降级）
    fee_model: { type: flat, rate: 0.0 }
alerts:
  channels: [log]                   # log / webhook
  criteria: { min_net_profit_margin: 0.02 }
```

关键配置项：

| 配置 | 作用 | 对应需求 |
|---|---|---|
| `refresh_interval_seconds` | 刷新频率（≤60s） | 1.3 |
| `staleness_threshold_seconds` | 过期阈值，默认 60s，可覆盖 | 8.3, 8.4 |
| `match_confidence_min` | 套利置信度门槛 | 4.5 |
| `signal_store_path` | 信号持久化路径；None/缺省=内存（重启丢失），文件路径=SQLite 持久化 | Phase 2 · 切片 B |
| `adapter_min_interval_seconds` | 相邻平台请求最小间隔（限流，0=不限流） | Phase 2 · 切片 C |
| `adapter_max_attempts` | 单次操作对底层的最大尝试次数（含首次） | Phase 2 · 切片 C |
| `adapter_backoff_base_seconds` | 指数退避基数（秒） | Phase 2 · 切片 C |
| `circuit_failure_threshold` | 连续失败达此数则熔断 | Phase 2 · 切片 C |
| `circuit_reset_timeout_seconds` | 熔断冷却时长，之后半开探测 | Phase 2 · 切片 C |
| `json_logging` | 结构化 JSON 日志开关：`true` 时根日志以单行 JSON 输出（便于集中式采集），默认 `false`（人类可读） | Phase 2 · 切片 D |
| `similarity_backend` | 匹配相似度后端：`lexical`（默认，纯词法）/ `normalizing`（词法 + 同义词/缩写归一，提升等价市场召回、减少漏信号） | Phase 2 · 切片 D |
| `platforms[].enabled` | 禁用平台则完全排除 | 7.3 |
| `platforms[].api_key_env` | 密钥缺失只禁用该平台 | 7.1 |
| `alerts.criteria` | 告警触发标准 | 6.2 |

## 4. 环境变量

| 变量 | 说明 | 默认 |
|---|---|---|
| `SCANNER_CONFIG` | 配置文件路径 | `config.yaml` |
| `KALSHI_API_KEY` | Kalshi API 密钥；缺失则仅禁用 Kalshi | 无 |
| `PREDICTFUN_API_KEY` | predict.fun 行情 API key（可选，作为 `x-api-key`）；省略 `api_key_env` 时缺失也可公开读取 | 无 |
| `SCANNER_WEBHOOK_URL` | 启用 webhook 告警通道时的目标 URL | 无 |
| `SCANNER_HOST` | `main()` 入口监听地址 | `127.0.0.1` |
| `SCANNER_PORT` | `main()` 入口监听端口 | `8000` |

## 5. 启动

```bash
# 默认加载 ./config.yaml
.venv/bin/python -m uvicorn scanner.app:app --host 127.0.0.1 --port 8000

# 指定配置文件
SCANNER_CONFIG=/path/to/my-config.yaml .venv/bin/python -m uvicorn scanner.app:app

# 启用 Kalshi（提供密钥）
KALSHI_API_KEY=你的密钥 .venv/bin/python -m uvicorn scanner.app:app
```

启动 `scanner.app:app` 时，FastAPI 的 lifespan 会同时拉起：
1. 每个启用适配器的摄取循环；
2. 周期性的下游流水线（重排名→匹配→套利→对账→告警）。

控制台入口 `scanner.app:main`（host/port 由 `SCANNER_HOST`/`SCANNER_PORT` 控制）效果相同。

## 6. 健康检查与可观测性

- `GET /health` 返回整体状态、市场/机会计数、各适配器健康与最近成功周期。
- 适配器失败、告警重试、流水线异常均通过标准日志记录（含适配器名）。建议生产接入集中式日志。

## 7. 安全说明（重要）

> 🔒 第一阶段读取 API **无任何鉴权 / 访问控制**，是只读接口，也**不执行任何交易**。

- **不要**将其直接暴露到不可信网络。请在前置部署带认证的反向代理 / API 网关（如 Nginx + 鉴权、云厂商 API Gateway）。
- API 密钥仅存在于适配器（经环境变量读取），**绝不**出现在 API 响应中。
- 若启用 webhook 告警，确认 `SCANNER_WEBHOOK_URL` 指向可信端点。

## 8. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| Kalshi 无数据 | `KALSHI_API_KEY` 未设置 | 设置该环境变量；日志会有「disabling this adapter only」提示 |
| `/opportunities` 为空 | 无价差 / 数据过期 / 置信度不足 | 检查 `/markets` 新鲜度、`/groups` 置信度、`match_confidence_min` |
| 某平台数据停更 | 抓取超时或出错被隔离 | 查日志中该适配器名的告警；其他平台不受影响 |
| 启动报缺依赖 | 未安装依赖 | 重跑 `pip install -e ".[dev]"` |
