# 06 · 测试策略

## 1. 总体方针

- **离线、确定性**：时间通过注入时钟控制，网络通过 `respx` mock。整个套件不发起真实网络请求，不依赖实时时钟，可复现。
- **测试驱动**：每个功能模块都配有独立测试；流水线层有跨组件集成测试。
- **正确性属性**：12 条不变式（Property 1–12）以示例/边界测试方式校验，覆盖关键业务保证。

当前状态：**616 个测试全部通过**（运行约 3 秒）。

## 3. 正确性属性（Property 1–12）

| 属性 | 内容 | 校验需求 |
|---|---|---|
| Property 1 | 所有 price/bid/ask ∈ [0,1] | 2.2 |
| Property 2 | volume/liquidity 为 None 或 ≥0 | 2.3 |
| Property 3 | 每条记录有 UTC `retrieved_at`，age 单调 | 1.4, 8.1 |
| Property 4 | 一个适配器失败不阻塞其他适配器 | 1.5 |
| Property 5 | 过期数据绝不进入套利结果 | 1.6, 8.2 |
| Property 6 | 组内每个市场的所有结果都被映射 | 4.6 |
| Property 7 | match_confidence ∈ [0,1]，低于阈值不进套利 | 4.4, 4.5 |
| Property 8 | 净利润率用 ask+费用算，且 net ≤ gross | 5.2 |
| Property 9 | 建议规模 ≤ 最薄腿流动性 | 5.6 |
| Property 10 | `/opportunities` 降序且无 ≤0 | 6.1, 6.4 |
| Property 11 | 失败通道每机会至多重试 3 次，清除前去重 | 6.5 |
| Property 12 | 禁用平台贡献 0 个市场 | 7.3 |
| Property 13 | 一个 group 活跃信号至多一个；CLOSED 后不复活（重现开新信号） | Phase 2 · 切片 A |
| Property 14 | 信号事件类型与状态转移一致，每 group 每周期至多一个事件 | Phase 2 · 切片 A |
| Property 15 | 相邻两次实际平台调用间隔 ≥ `min_interval` | Phase 2 · 切片 C |
| Property 16 | 单次操作对底层适配器的调用次数 ≤ `max_attempts` | Phase 2 · 切片 C |
| Property 17 | 熔断状态机：达阈值打开、冷却内快速失败、半开探测恢复 | Phase 2 · 切片 C |

## 4. 如何运行

```bash
# 全部测试
.venv/bin/python -m pytest

# 安静模式 + 摘要
.venv/bin/python -m pytest -q

# 单个文件
.venv/bin/python -m pytest tests/test_arbitrage.py -v

# 按关键字
.venv/bin/python -m pytest -k "matching"
```

`pyproject.toml` 已配置 `asyncio_mode = "auto"`，异步测试无需额外装饰。

## 5. 测试基础设施

- **`tests/adapter_contract.py`**：可复用的 `AdapterConformanceTests` 基类（任何新适配器子类化并提供 `adapter` fixture 即可验证 Req 7.2）+ `FakeAdapter`（支持脚本化逐周期 `responses`、`fetch_delay`、`fetch_error` 注入）。
- **`tests/fixtures/`**：录制的 JSON fixture（Polymarket Gamma/CLOB、Kalshi markets，含缺失字段样本），供适配器测试用 respx 回放。
- **注入时钟**：摄取、套利测试通过 `clock` 回调控制时间，使过期/年龄判定确定。

## 6. 新增功能的测试要求

- 新模块必须带单元测试，覆盖正常路径 + 边界。
- 涉及新平台：子类化 `AdapterConformanceTests` 跑通一致性套件，并加录制 fixture。
- 涉及新的业务不变式：在 `design.md` 增补 Property 并补对应测试，更新本文件表格。
- 改动后务必全量跑通 `pytest` 再提交。
