# 01 · 业务背景

## 1. 什么是预测市场

预测市场（Prediction Market）是允许用户就未来事件结果下注/交易的平台。每个市场对应一个可证伪的问题（例如「比特币 2025 年是否会突破 10 万美元」），用户买卖与各结果挂钩的合约。合约价格在 0 到 1 之间，可被解读为市场对该结果发生的**隐含概率**。当事件结算时，正确结果的合约价值为 $1，错误结果的合约价值为 $0。

代表性平台：

- **Polymarket** —— 基于链上的预测市场，提供公开的 Gamma API（市场发现）和 CLOB API（订单簿/价格），无需鉴权。
- **Kalshi** —— 受美国监管的事件合约交易所，提供 REST API（`trade-api/v2`），价格以「分（cents）」计，费用按非线性公式收取，部分接口需要 API 密钥。

## 2. 业务问题：跨平台套利

同一个现实世界事件，往往在多个平台上都有对应市场。由于各平台的用户群体、流动性、信息流不同，**同一事件在不同平台上的定价会出现差异**。当差异足够大时，就存在无风险（或近无风险）的套利机会。

### 套利原理（二元市场）

对一个二元（YES/NO）市场，若在 A 平台买入 YES、在 B 平台买入 NO，则无论事件结果如何，组合中必有一份合约结算为 $1。因此：

```
组装一对合约的成本 = ask_YES(A) + ask_NO(B)
```

如果这个成本 **小于 1**，那么花费不到 $1 就锁定了 $1 的确定回报，差额即为利润。计入两个平台的交易费用后：

```
净成本     = (ask_YES(A) + ask_NO(B)) + 费用
净利润率   = (1 - 净成本) / 净成本
```

只要净利润率为正，就是一笔有利可图的套利。系统的核心使命，就是**实时、准确地发现这类机会，并在价差消失前提示用户**。

### 为什么这件事不简单

1. **价格会过期**：预测市场价格变动快，几十秒前的价差可能已经消失。基于陈旧数据行动会亏损。→ 系统必须有严格的**新鲜度保证**。
2. **跨平台「同一事件」难判定**：两个平台对同一事件的标题措辞不同（"Will Bitcoin close above $100,000 in 2025?" vs "Bitcoin above 100000 by 2025"），甚至 YES/NO 表述相反。→ 系统需要一个可解释的**匹配引擎**。
3. **费用是非线性的**：Kalshi 的费用是 `0.07 × p × (1-p)` 每合约，依赖价格而非固定费率。→ 套利计算必须精确计入各平台的真实费用。
4. **必须跨越价差成本**：能成交的是 ask 价（卖一），不是中间价。用中间价计算会高估利润。→ 套利用 **ask 价**计算。

## 3. 目标用户

| 用户角色 | 诉求 |
|---|---|
| 交易者（Trader） | 看到高交易量/高流动性的市场，发现并快速响应套利机会，配置告警 |
| 系统运维（Operator） | 通过配置增删平台，无需改代码即可扩展 |
| 系统集成方（Integrator） | 通过统一的规范模型和稳定 API 消费数据，对接未来的聚合功能 |

## 4. 系统能做什么（第一阶段范围）

- ✅ 实时摄取多平台行情，规范化为统一模型
- ✅ 按交易量 / 流动性对市场排名与过滤
- ✅ 跨平台匹配等价市场，输出匹配置信度
- ✅ 检测套利机会，计入费用与价差，按流动性限制建议规模
- ✅ 通过只读 API 呈现市场、组、机会，附带数据新鲜度
- ✅ 满足条件时通过告警通道（日志 / Webhook）通知，带重试与去重

## 5. 系统不做什么（第一阶段非目标）

- ❌ **自动下单 / 执行交易**：系统只检测与呈现，不替用户交易。
- ❌ **精致的 Web 前端 UI**：第一阶段只提供 JSON API 与控制台视图。
- ❌ **历史回测与分析存储**：仅保留新鲜度/告警所需的实时快照。

## 6. 业务价值与扩展方向

第一阶段刻意围绕「可插拔的平台适配器 + 稳定的读取 API」构建，使得后续价值能够低成本叠加：

- 接入更多平台（Manifold、PredictIt 等）只需实现一个适配器，核心逻辑零改动。
- 稳定的 API 是未来「预测聚合器」「自动执行引擎」等高阶功能的数据底座。
